## 8. 逻辑架构（技术无关分层，不点名任何框架或中间件）

| 层 | 职责 | 失败时的行为 |
| --- | --- | --- |
| L0 接入层 | 统一对外接口；统一返回结构；入参校验 | 返回 `ok=false` + 错误码，不抛裸异常 |
| L1 证据与版本层 | 只读读取 HIS 名单快照；记录来源 ID、版本 / 时间、刷新状态 | 数据超周期 → 标"待刷新"并停止下游，历史快照不得当当前状态使用 |
| L2 确定性策略层 | **安全审查、权限校验、人工确认**三道硬卡；不可逆动作前置校验 | 命中任一红线 → 硬拒绝，不进入模型层，不降级为"模型自行判断" |
| L3 模型辅助层 | 仅限：排程建议、患者陈述结构化预填初稿、不确定项标注 | 低置信 / 缺资料 / 冲突 / 越权 → 转具名人工接收人 |
| L4 人工确认与交接层 | 护士确认、专科核对、接手人确认；六要素交接包完整性校验 | 未确认 → 待办不结项、原记录不覆盖、责任不转移 |
| L5 审计与留痕层 | 动作输入、责任角色、前置条件、副作用、原记录、版本、时间戳 | 审计缺项 → 动作不予生效 |

**设计原则**（来自资料的方法框架，非技术选型）：

- 不要把模型置信度等同于业务风险；优先选择高价值、可拦截、可恢复的切入点【证据：访谈记录-report.md 193-195】。

## 15. 本阶段最可能出问题的地方

1. **技术栈与数据红线为空**：需求方 brief 两节为空，若按"看起来合理"的默认值选型，直接违反"不许替换框架 / 不引入未要求中间件"。这是本阶段最大风险。
2. **把训练材料当授权**：标准参考答案、评分评语、REQ 条目都是训练 / 假设资料，不是客户签字需求；傅景未访谈，权限与合规结论不能预设。
3. **把"12 分钟 / 4 分钟""85% 完成率"写进代码或验收基线**：前者是未验证估算，后者分母未固定。
4. **红线靠模型自觉遵守**：危险信号、覆盖原记录、HIS 写入、责任转移必须做成确定性硬卡，不能只写在提示词里。
5. **版本与刷新状态被忽略**：历史快照伪装成当前状态，会直接污染随访结论【f34】。
6. **证据编号归属错配**：资料中已出现 f53 错挂顾明岚（实际来自叶书）等归属错误，方案与代码注释引用编号时须逐条核对【证据：业务挖掘报告 55、61】。
7. **"每行代码加注释"与"中文 docstring"导致实现阶段返工**：需在 S1 就把模板固化。
